## 修复：视频分析「录屏未授权」假象 + Android 10+ 后台录屏限制
- 现象：用户在「模型」页授权录屏后仍报 STATUS「录屏未授权，无法分析」。
- 根因1（假象）：`ModelSettingsScreen` 授权回调里 `captureAvailable = true` 无条件设置，而 `startForegroundService` 异步，若 `ScreenCaptureService.onStartCommand` 任一步抛异常则 Service 静默崩溃、`instance` 永为 null，UI 却显示「已授权」。
- 修复1：`ScreenCaptureService.onStartCommand` 加 try/catch 打印明确失败原因 + 注册 `MediaProjection.Callback.onStop` 日志；`ModelSettingsScreen` 改为 LaunchedEffect 轮询 `ScreenCaptureService.isAvailable()` 实时反映真实状态，测试按钮在 instance==null 时直接报错；通知 smallIcon 改用 `R.mipmap.ic_launcher`。
- 根因2（平台限制）：Android 10+ 要求 MediaProjection 录制方 App 保持前台，切到抖音（App 退后台）系统会 `onStop` 录屏。
- 修复2：新增 `ui/KeepAliveActivity`（透明主题 + FLAG_NOT_FOCUSABLE|FLAG_NOT_TOUCHABLE + 1x1 窗口 + singleInstance），`startVideoWatch` 授权后启动、`stopVideoWatch` 发 `ACTION_STOP_KEEPALIVE` 广播关闭，使 App 在分析期间保持前台，绕过后台录屏停止。manifest 注册该 Activity + `res/values/themes.xml` 加 `Theme.Transparent`。
- 诊断：真机失败时用 `adb logcat -s ScreenCaptureService` 看启动失败原因；模型页「录屏服务运行中」状态实时反映。

## 关键坑修复：MediaProjection 授权 resultCode == -1 即「成功」
- logcat 报 `缺少录屏授权数据(resultCode=-1)` 的根因：`Activity.RESULT_OK` 的值就是 `-1`（授权成功），`Activity.RESULT_CANCELED` 才是 0。原判断 `if (resultCode == -1 || data == null)` 把「成功」当成「缺省/失败」，服务一启动就 self-stop。
- 修正：`ScreenCaptureService.onStartCommand` 改为 `if (resultCode != Activity.RESULT_OK || data == null)` 才停止，并 import `android.app.Activity`。
- 通用经验：MediaProjection 授权必须按 `resultCode == Activity.RESULT_OK && data != null` 判定成功，**绝不能把 -1 当缺省/失败**。

## 迭代：散步模式（自动切下一个视频 + 决策结果提示）
- 用户需求：抖音首页推荐流播放时启动「散步模式」，每视频截前 10 秒随机几帧 → 大模型识别 → 按本地点赞/收藏条件自动点赞/收藏 → 顶部气泡提示结果 → 自动切下一个视频继续。
- 关键改动 `DouyinAccessibilityService.kt`：
  1. `accessibility_service_config.xml` 中 `canPerformGestures="true"` 是**唯一**能开启手势的途径。`onServiceConnected` 里**不能用 `AccessibilityServiceInfo()` 全新实例 + `setServiceInfo`**（会把 XML 的 canPerformGestures 重置为默认 false，反而关掉手势）。正确做法：`val info = serviceInfo ?: AccessibilityServiceInfo()` 取「已按 manifest 填充」的实例（canPerformGestures 已为 true），只改 `flags` 后 `setServiceInfo(info)`。**三个坑都踩过**：① `FLAG_CAN_PERFORM_GESTURES` 不存在（Unresolved）；② `FLAG_REQUEST_CAN_PERFORM_GESTURES` 同样 Unresolved（公共 SDK 里是 `@hide`，不进 android.jar）；③ `canPerformGestures = true` 赋值报错（该属性只读、类型非 Boolean，无法赋值）。结论：手势能力代码层无法开关，纯靠 manifest XML。
  2. 新增 `goToNextVideoByGesture()`：`dispatchGesture` 向上滑动（抖音切下一个视频标准手势，startY=0.82h→endY=0.18h，300ms）；`advanceToNextVideo()` 改为「手势优先，失败退化为 scroll」。
  3. 新增 `notifyUser()`/`showTransientToast()`：用 `TYPE_ACCESSIBILITY_OVERLAY` 在抖音顶部居中显示约 2.8s 临时气泡（文案如「视频：xxx / 已点赞+收藏」），**必须在 Dispatchers.Main 执行 WindowManager 操作**（serviceScope 默认 Dispatchers.Default，addView 需 Looper 故切 Main）。
  4. `analyzeAndAct` 增加 `buildDecisionMessage()` 拼装「已点赞/已收藏/建议点赞/跳过」提示；自动点赞/收藏后调用 `notifyUser`。
  5. `startVideoWatch` 循环改为：detectVideoIdentity 变化 → 分析+执行+提示 → `advanceToNextVideo()` → 等 2.6s 加载下一个；同一视频停留 >6s 自动重试切换（`lastAdvanceTime`）。重置 `isAnalyzingVideo/lastVideoIdentity`。
  6. 悬浮菜单文案「视频分析」→「散步模式」（开始/暂停/继续/结束），保留手动「下一视频(手动)」。
- 注意：改 canPerformGestures 后用户需在系统设置里重新开启本无障碍服务（metadata 变更需重授权）。
