- 评论发送流程优化（用户反馈「内容写到输入框后还没点发送按钮就关闭了输入法」）：
  - 根因：`ensureCommentTextBeforeSend` 点按输入框后只 delay 400ms，键盘可能没弹起（或被收起），导致后续找不到发送按钮
  - 修复：
    1. `ensureCommentTextBeforeSend` 点按后 delay 500ms → 验证键盘弹起（输入框仍可见）→ 没弹起则重走写入流程
    2. 发送后 delay 1秒（让评论真正发出去）
    3. 发送结果验证（文本还在则重试）
    4. performGlobalAction(GLOBAL_ACTION_BACK) 收起键盘 → delay 1秒
    5. closeCommentPanel 关闭评论区
  - 现在流程：写入 → 点按唤回键盘 → 验证键盘弹起 → 点击发送 → 等1秒 → 收键盘 → 等1秒 → 关评论区

- 评论按钮定位二次重构（用户反馈「寻找评论按钮还是不行，现在直接点了点赞按钮和收藏按钮」）：
  - 误点根因：上一版（findCommentButton 五级策略）仍对「评论按钮的可点击节点」执行 `performAction(ACTION_CLICK)`——抖音右栏按钮的可点击祖先常是**包住多个按钮的大容器**，点击落在容器中心会误中点赞/收藏；且 C/D 策略「收藏上方最近的节点」「赞下方最近的节点」选中的也可能就是这个大容器节点本身。
  - 二次重构方案（`findCommentButtonTarget(): Point?` + `scanWindowForCommentTarget`）：**彻底弃用节点 performAction 点击，改为语义锚点矩形推导目标点 + dispatchTap 手势点按**：
    - **A** comment-id 节点中心；
    - **B** 右栏「评论」文字/描述节点中心；
    - **C 双锚点夹逼（主力）**：赞按钮底边与收藏按钮顶边的**中点**——右栏固定布局「赞→评论→收藏→分享」，该点必然落在评论按钮上且天然不可能是赞/收藏/分享；同列校验（cx 差 ≤ max(40, 较窄按钮宽/2)）、gap ∈ 1..屏高/6；
    - **D** 收藏单锚点：收藏正上方半个按钮高度处；**D2** 赞单锚点：赞正下方半个按钮高度处（评论与相邻按钮同尺寸紧贴堆叠）。
  - 锚点实现细节：`anchorNodeOf` 取右栏（cx ≥ 55% 屏宽）内**最靠上**的语义匹配节点（防误中底部唱片等）；`buttonRectOf` 优先取尺寸合理的可点击祖先（高 ≤ 屏高/5、宽 ≤ 屏宽/4、包住文字节点），否则用节点矩形向上扩 2 倍高度近似（图标在文字上方）。
  - 删除了几何聚类策略（E）——它的「底部固定三个」假设正是误点来源之一；锚点全不可识别（纯图标无文字/描述/id）时返回 null 交给 VLM 视觉定位兜底。
  - tryClickCommentButtonByA11y 改为「找点 → dispatchTap」，不再持节点引用；日志 `评论按钮目标点命中[A|B|C:赞收藏夹逼|D:收藏上方|D2:赞下方]: (x, y)`。
  - 未做 Gradle 编译（本机无 wrapper/SDK），需用户本地 `./gradlew assembleDebug` 验证。

- 评论发送「无内容」修复（用户反馈「内容已成功粘贴进输入框，但还没发送就隐藏了输入法，发送时提示无内容」）：
  - 根因：**SET_TEXT 假成功**——抖音自定义输入弹窗上 `ACTION_SET_TEXT` 只更新无障碍节点文本（视觉可见、读回验证通过），但不触发 App 的文本监听（TextWatcher）→ App 内部编辑缓冲区为空 → 点击发送时 App 先收起 IME（用户看到的「键盘被隐藏」正是发送点击的第一步）再校验缓冲区 → 「无内容」toast。旧的读回验证（commentTextLanded 读节点 text）无法区分「节点文本已更新」与「App 缓冲区真正有内容」。
  - 五项修复（全在 `DouyinAccessibilityService.kt`）：
    1. **写入尝试重排，PASTE 优先**：typeCommentText 顺序改为 a) 点按激活+清空+剪贴板 PASTE（走真实编辑管线，触发 App 文本监听，缓冲区同步更新）→ b) FOCUS+SET_TEXT → c) 点按激活+SET_TEXT。
    2. **发送按钮启用状态双重验证**：tryWriteComment 在读回通过后追加 `isSendButtonReady(text)`——抖音发送按钮在缓冲区为空时禁用（置灰），以此识别假成功并降级尝试（日志「文本已显示但发送按钮仍禁用（App 缓冲区为空），判为假成功」）。
    3. **跨窗口发送按钮搜索** `findSendButtonInWindows(preferredText)`：遍历 service.windows（FLAG_RETRIEVE_INTERACTIVE_WINDOWS 早已开启），锁定「输入框所在窗口」（优先 EditText 文本含 preferredText 的窗口=输入弹窗），仅在该窗口取「可点击+文案命中 COMMENT_SEND_TEXTS+屏幕下半部」节点，启用优先+最靠底部；防止 rootInActiveWindow 在面板/弹窗窗口间切换导致漏找，也防止误点评论区里恰好含「发送」字样的评论项。配套 waitForSendButton 轮询。
    4. **发送前 ensureCommentTextBeforeSend**：输入框消失（键盘收起连带弹窗收起）→ 重走 typeCommentText；文本丢失 → 重写；文本仍在 → 点按输入框重新聚焦唤回键盘（delay 400）。

  - import 新增 `android.view.accessibility.AccessibilityWindowInfo`。performComment KDoc 同步更新（步骤 3/4）。
  - 验证日志链：`adb logcat -s DouyinA11yService`——正常链「评论内容已写入输入框（点按激活 + 剪贴板 PASTE）→ 评论内容：xxx」；假成功链「文本已显示但发送按钮仍禁用…判为假成功」；异常链「发送按钮禁用（App 缓冲区为空），补救 PASTE 写入一次」「发送后文本仍在输入框，手势重试发送一次」。
