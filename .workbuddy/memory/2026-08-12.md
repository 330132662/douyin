## 修复：日志只在打开日志页时才记录（看不到历史评论）
- 现象：用户反映"记录的评论列表在哪，看不到"。
- 根因：`addLog` 只转发给实时 `logListener`；`LogScreen` 仅在组合时设置该监听，且 `logs` 列表 `remember` 在离开页面后清空、再次进入重建为空。所以页面未打开期间扫描的评论全部丢失，打开页时也只显示实时新增的。
- 修复：在 `DouyinAccessibilityService` 增加 `logHistory`（`Collections.synchronizedList`，上限 2000，addLog 时写入）+ `getLogHistory()` 快照；`LogScreen.LaunchedEffect` 进入时先 `instance?.getLogHistory()?.let { logs.addAll(it.asReversed()) }` 预加载历史，再设置实时监听。
- 现状：日志仍在内存（服务进程存活期间保留），服务被系统杀掉则丢失；如需跨进程持久化可改用 DataStore/文件。

## BUG 修复：翻页遇意向客户静默停止 + 没进主页
- 现象：翻几页遇到意向客户后翻页直接停、且不进主页，无任何日志。
- 根因：`findUserClickableNode` 当目标文本节点自身可点击时 `clickable == match`，原代码 `match.recycle()` 后返回同一已回收节点 → 调用方 `entry.performAction(ACTION_CLICK)` 抛 `IllegalStateException: Cannot perform this action on a recycled node` → 异常穿透翻页协程外层 catch（仅 Log.e 不写日志）→ 翻页协程崩溃停止。
- 修复：
  1. `CommentScanner.findUserClickableNode`：仅在 `clickable != null && clickable != match` 时回收 match，否则返回 match 由调用方回收（消除回收竞态）；昵称匹配由精确相等放宽为"相等或 startsWith"（兼容 emoji/后缀）；空 username 直接返回 null。
  2. `DouyinAccessibilityService.startPageFlip` 循环内对 `followUserViaProfile` 调用外包 try-catch，记录"关注流程异常"，确保任一意向客户处理出错都不再拖垮整个翻页循环。
- 验证：沙箱无 gradlew 未编译；本地 `./gradlew assembleDebug` 验证。若仍进不去主页，看日志是"未在当前评论区找到用户入口"（匹配/提取问题）还是"点击用户入口失败"。
